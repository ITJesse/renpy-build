# RenPyLinter iOS engine source audit

Status: 8.5.3 native macOS build implementation under validation; no engine release yet.

## Baselines

`tools/runtime/versions.json` records eight official `renpy/renpy-build` tag commits,
verified directly with `git ls-remote https://github.com/renpy/renpy-build.git`.
The independent `renpy/renpy` tag commits are also pinned. 7.5.3 and 8.0.3 share
an upstream build-system commit, and an engine-source commit, but use different Python versions.
No version branch is derived from the latest branch.

## Build route

The upstream entry is `build.sh` -> `renpybuild/__main__.py` -> ordered `tasks`.
Upstream assumes Ubuntu, LLVM and archived Apple SDKs. `tools/runtime/native.py`
uses those task functions with Apple's macOS toolchain and a locked Xcode/SDK.
It keeps upstream `tmp/build`, `tmp/host`, `tmp/source`, `tmp/install.ios-arm64`
and `tmp/install.ios-sim-arm64`. No build or cache directory is redirected.
Only arm64 device and arm64 simulator are requested. The `renios.py` universal
collector requires sim-x86_64; this scoped packager reads the two actual arm64
install directories directly and rejects additional architecture slices.

`python3.py` builds CPython from the tagged source archive with the upstream
cross-Darwin and iOS patches. Each target generates its own pyconfig.h and uses
only that build's headers. The host interpreter exists solely for build tools.
`librenpy.py` compiles the statically registered Ren'Py extensions and pyobjus;
`renpython.py` creates librenpython.a from the tracked launcher source.
Dependencies are build intermediates; only the three engine libraries and
matching Python resources/headers are engine-package deliverables.

## Host patch ownership

Read-only reference: RenPyLinter-ios/docs/librenpython-edits-summary.md.
The Python 3 launcher malloc-zone patch is recovered into tracked
runtime/librenpython3.c: install RAW/MEM/OBJ allocators before preinitialization,
set PYMEM_ALLOCATOR_NOT_SET, restore allocators after Python returns, pressure
relief, destroy zone. Pymalloc remains enabled. This preserves the documented
launcher patch; it does not redesign or prove restart lifecycle safety.

The application owns its main.py adaptations: quit interception, iOS stubs,
RENPY_COMMON_PATH writable common staging, and Python-2 pyobjus enum workaround.
The application also owns helper_tool.rpy and its SwiftBridge command protocol.
The core package ships upstream renpy.py as main.py and upstream common resources.
A future consumer MUST explicitly reapply/version the application's host overlay
rather than replace those scripts with the package defaults. This change does
not edit the application or implement its Release consumption.

Python resources ship as source, with no pyc/rpyc generated by a mismatched host.
Native modules must remain present in librenpy's inittab; stdlib source alone
is not proof of native extension completeness.

## Compatibility and validation boundaries

SDL2, FFmpeg, MetalANGLE, Live2D and other low-level libraries remain host-owned.
The build dependencies are pinned to the version branch's upstream recipes.
CI link checks against rebuilt dependencies and local links against the actual
application dependencies are distinct checks. A successful static archive build
is not link proof. A successful link is not a game execution or restart test.

Live2D 8.5.3 uses the newer csmGetRenderOrders ABI, while older engines use the
legacy csmGetDrawableRenderOrders ABI. The application's documented legacy
Live2D library lacks arm64 simulator support; do not substitute x86_64 or claim
that passing a core engine link validates dynamically resolved Cubism symbols.
